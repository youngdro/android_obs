## 1. 准备接收端（任选一种）

```bash
# A. MediaMTX（推荐，单文件）：https://github.com/bluenviron/mediamtx/releases
./mediamtx                      # 默认监听 rtmp://<电脑IP>:1935
ffplay rtmp://<电脑IP>:1935/live/test          # 播放确认
ffmpeg -i rtmp://<电脑IP>:1935/live/test -c copy record.flv   # 录制以便逐帧检查

# B. 只用 ffmpeg（一次性接收并录制）
ffmpeg -listen 1 -i rtmp://0.0.0.0:1935/live/test -c copy record.flv
```

App 推流地址填写：`rtmp://<电脑IP>:1935/live/test`。也可以填 B 站、抖音、YouTube 等平台给的地址和 Stream Key（RTMPS 请填 `rtmps://`）。

## 2. 最小 Demo 验证步骤（第一个交付节点）

1. 安装 APK，授权摄像头和麦克风。
2. 默认已经添加了一个铺满画布的网页图层，加载内置测试页。确认顶部显示“网页：已加载（实测视口 1920×1080 CSS px）”。
3. 填写推流地址，点击“开始推流”，状态依次显示“连接中 → 直播中”，并显示时长、帧率、码率。
4. 在接收端播放 / 录制，逐项核对：

| # | 检查点 | 通过标准 |
| --- | --- | --- |
| D1 | 完全透明 | 画面中间是摄像头，没有白底/黑底 |
| D2 | 半透明 | 50% 蓝色块后能看到摄像头；透明度阶梯 0/25/50/75/100 逐级变化；文字阴影、圆角无黑边 |
| D3 | 透明图片 | 旋转的 PNG 圆环边缘平滑，SVG 星形渐变到透明 |
| D4 | 动画 | 红球左右移动、Canvas 小球和波浪、计数器持续变化（接收端录像中计数连续） |
| D5 | 数据更新 | 用 `overlay-server` + `?ws=`，接收端看到“值”每秒 +1；在服务器终端输入文字后接收端更新 |
| D6 | 视口 | 四角青色 L 形标记完整可见 |
| D7 | 一致性 | 接收端构图与手机预览一致；选中框等编辑 UI 不出现在接收端 |
| D8 | 刷新 | 直播中点“刷新”，接收端不出现白屏；摄像头不中断 |
| D9 | 加载失败 | 改成不存在的地址：网页图层从输出中消失，摄像头继续，手机上显示错误 |
| D10 | 静音 | 点麦克风静音，接收端声音同步消失，电平条归零 |

5. **采集模式对比（决定正式方案）**：“推流设置 → 网页 GPU 采集”开 / 关各测一次，记录：
   - 接收端网页是否正常显示（GPU 模式在个别机型上可能出现黑块、空白或不刷新）；
   - 状态栏输出帧率（目标 ≥ 28fps）；
   - 10 分钟后的机身温度。
